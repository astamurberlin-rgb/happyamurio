# Проверки Happy: что есть и что каждая смотрит

Это справочник. Запускать нужно только то, что относится к сделанной правке.

## Общие проверки — папка `scripts/`

Запуск: `node scripts/имя`. Папки текущих выпусков проверки берут сами из `shared/apps.json`.

| Проверка | Что смотрит |
| --- | --- |
| `check-shared.mjs` | Копии общих файлов в текущих выпусках побайтно совпадают с эталоном. Известные расхождения показывает предупреждением. |
| `check-shared-ui.mjs` | Общая карточка входа и порядок разделов настроек одинаковы в трёх приложениях: одна строка состояния и кнопка «Открыть последнюю версию»; в Meal осталась только выгрузка дневника. |
| `check-layout.mjs` | Страницы разбираются без ошибок, версия на странице совпадает с `shared/apps.json`, Day, Meal и Sport запускаются на общем модуле и не знают прежних ячеек хранения и входа, старые адреса ведут на текущие выпуски. |
| `check-happy-store.mjs` | Вход и общий модуль хранения и обмена: у каждого приложения свой вход, выход закрывает только свой вход на сервере, прежняя общая ячейка удаляется; запись только после входа, запись без сети, два устройства, две вкладки, условная запись, второй аккаунт, только свои документы, витрина и общие документы, номер формата, места в списке, первый обмен на новом устройстве. |
| `check-measurements.mjs` | Замеры тела — общий документ и общий экран: чтение, новый замер, правка, удаление и возврат, CSV, совместимость с записями Sport 42. |
| `check-sport-summary.mjs` | Витрина Sport: сводка тренировок без демо и без подходов, плановые занятия в окне, разбор по одной записи, итоги дня. |
| `check-food.mjs` | Витрина питания: сводка и счётчики еды Meal, нажатия трёх приложений и одно число на счётчике, отметка «счётчик убран со страницы», «съедено» — прибавить непосчитанное, не удвоить посчитанное, вычесть снятое. |
| `check-app-links.mjs` | Свитчи связи между приложениями: включение и выключение пары в обе стороны, одна запись на пару. |
| `check-meal-exports.mjs` | Выгрузки Meal: CSV, отчёты, PDF, названия способов приготовления. |
| `check-selfcare.cjs` | Отметки самочувствия Day: сохранение, группировка, пустые и нейтральные отметки. |
| `check-gradients.mjs` | Движок градиентов для студий. |
| `check-studio-account.mjs` | Вход в студиях отдельный от входа в приложениях. |

## Meal — папка `meal-32/checks/`

Запуск: `node meal-32/checks/имя`. Проверкам каталогов нужна ветка `meal-libraries` в том же репозитории.

| Проверка | Что смотрит |
| --- | --- |
| `check-meal-docs.mjs` | Дневник Meal в общем модуле: раскладка на документы и обратно без потерь; каждая запись еды, продукт, счётчик и раздел — отдельная запись; правки с двух устройств сводятся по записям; начальные разделы и счётчики не записываются и не затирают настроенное на другом устройстве; порции соседей не хранятся; без изменений ничего не пишется; скорость на годе записей. |
| `check-supplements-store.mjs` | Свои БАДы и приёмы в документе общего модуля: вид ↔ записи, один снимок на версию состава, без входа запись не принимается, два устройства сходятся. |
| `check-meal-first-time.mjs` | Время приёма — первый продукт; правило приёма по калорийности; счётчики добавок; сводка для Day. |
| `check-desserts.mjs` | Каталог десертов читается из файла библиотеки. |
| `check-search-names.mjs` | Русские поисковые названия для BLS и USDA. |
| `check-catalog-offline.mjs` | Каталоги без интернета: скачивание, копия, повреждённая копия. |

`store-model.mjs` — не проверка, а модель общего модуля для первых двух проверок: запись остаётся с поздней правкой, удаление — тоже правка.

`check-shop.mjs` сравнивает витрину с каталогами того коммита библиотек, на котором собран выпуск. Запускать так: `HAPPY_LIBRARIES_REF=4261588 node meal-32/checks/check-shop.mjs`.

## Sport — папка `sport-43/`

1. Собрать: `node sport-43/scripts/build-release.mjs`.
2. Проверить: `npm --prefix sport-43/sport run check`. Это около сорока проверок одной командой. Раскладку записей Sport на документы общего модуля и места в списках смотрит `check-sport-docs.mjs`.

Сборка может изменить `sport-43/index.html`. Если выпуск не планировался, вернуть файл: `git checkout -- sport-43/index.html`.

Отдельно, в браузере: `node sport-43/scripts/check-settings-layout.mjs` (экран настроек) и `node sport-43/scripts/check-families.mjs <адрес>` (семейства упражнений). Хранение и обмен Sport в браузере — сценарий `sport_store` ниже.

## Сценарии в браузере — папка `scripts/browser/`

Сценарий открывает настоящие страницы Day, Meal и Sport в Chrome без окна и проходит путь человека: вход, запись еды, нажатие на счётчик, переход между приложениями. Так находится то, чего не видят проверки отдельных файлов: запаздывания, двойной счёт, лишние запросы.

Записи придуманные. Настоящий аккаунт и сервер не используются: запросы перехватываются в браузере, отвечает поддельный сервер из `common.py`.

Запуск всех: `scripts/browser/run.sh`. Запуск выбранных: `scripts/browser/run.sh имя имя`. Полный набор идёт около десяти минут. Код возврата 0 — все сценарии прошли.

Что нужно до запуска:

- Python с Playwright и Chrome.
- Собранный Sport: `node sport-43/scripts/build-release.mjs`.
- Собранный Day одним файлом: `python3 scripts/build-day-standalone.py day-59`.
- Ветка каталогов в том же репозитории: `git fetch --depth=1 origin meal-libraries:refs/remotes/origin/meal-libraries`.

Настройки — переменными окружения:

| Переменная | Что задаёт | По умолчанию |
| --- | --- | --- |
| `HAPPY_MEAL`, `HAPPY_DAY_STORE`, `HAPPY_SPORT_STORE` | Выпуски Meal, Day и Sport для сценариев. | `meal-32/`, `day-59/`, `sport-43/` |
| `HAPPY_LIBRARIES_REF` | Ветка или коммит каталогов Meal. | `origin/meal-libraries` |
| `HAPPY_CHROME` | Путь к Chrome. | `/usr/bin/google-chrome` |
| `HAPPY_PORT` | Порт временного сервера. | `8767` |
| `HAPPY_OUT` | Куда писать результаты: `имя.json` и `имя.log`. | `/tmp/happy-browser` |

Сценарий `versions` читает адреса из `shared/apps.json`, переменные выпусков на него не действуют.

Как писать новый сценарий:

- Начало файла: `from common import *`.
- «Телефон» — `phone(browser, имя)`: своё хранилище, экран 393×852, московское время. Один телефон с тремя приложениями — три страницы одного `phone`.
- Каталоги Meal без сети — `libraries(ctx)`. `state["offline"]=True` обрывает запросы, `hold={имя файла}` придерживает ответ, чтобы проверить отмену.
- Сценарии не запускать с 23:50 до 00:10 по московскому времени: часть шагов пишет «сегодня» и тренировку в 00:05, на границе суток `meal_store` и `meal_supplements` не проходят без ошибки в приложении.
- Более новую версию приложения изображает вкладка-заглушка: `stand_in_route(ctx)` и `stand_in(ctx, [приложение, документы, чтение, номера форматов])` с номером формата новее.
- Приложения записывают только после входа. Быстрый вход придуманным аккаунтом — `enter(page, 'meal' | 'day' | 'sport')`; у каждого приложения вход свой — соседнее приложение на том же телефоне входит своим `enter`. Путь человека через карточку входа проверяют `meal_store`, `day_store` и `sport_store`.
- Кольцо энергии читают `he(page, id, вид)` в Sport и Day и `er(page, вид)` в Meal. Вид — «съедено», «баланс» или «потрачено».
- Ждать только через `wait_for(page, условие, секунды)` или `page.wait_for_timeout`. Во время `time.sleep` поддельный сервер не отвечает, и страница его «не видит».
- «Вернулся в приложение» — `page.bring_to_front()` и событие `visibilitychange`.
- В конце — `sys.exit(finish(имя, out, checks))`.
- Числа в проверках — от придуманных записей самого сценария. Личные данные и настоящие аккаунты не использовать.
- Новый сценарий дописать в список внутри `run.sh` и в таблицу выше.

## Команды, которые меняют файлы

Это не проверки. После каждой смотреть, что изменилось.

| Команда | Что делает |
| --- | --- |
| `node scripts/sync-shared.mjs` | Копирует общие файлы из `shared/` в текущие выпуски. |
| `node scripts/sync-shared-ui.mjs` | Встраивает общий стиль настроек в страницы Day и Meal. |
| `python3 scripts/build-day-standalone.py day-59` | Собирает Day одним файлом `Happy-Day-59.html`. |
| `python3 scripts/refresh-provenance.py day-59 meal-32` | Обновляет список файлов выпуска с контрольными суммами. С `--check` только сверяет. Запускать после последней правки кода и `git add -A`. Справки `.md` в список не входят: после правки справки ничего запускать не нужно. |
| `node sport-43/scripts/write-provenance.mjs`, затем `verify-release.mjs` | То же для Sport. |
| `python3 -I scripts/build-meal-lab.py meal-32 папка` | Собирает копию Meal для показа на телефоне до выпуска. |

При новом выпуске в этом файле меняются только номера папок.
