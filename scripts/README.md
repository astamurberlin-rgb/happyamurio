# Справочник исполнителя Happy: проверки, сборка, что где лежит

Это справочник. Запускать нужно только то, что относится к сделанной правке.

## Общие проверки — папка `scripts/`

Запуск: `node scripts/имя`. Папки текущих выпусков проверки берут сами из `shared/apps.json`.

| Проверка | Что смотрит |
| --- | --- |

| `check-shared.mjs` | Копии общих файлов в текущих выпусках побайтно совпадают с эталоном. Известные расхождения показывает предупреждением. |
| `check-shared-ui.mjs` | Первый экран, вход, профиль и цели — общие файлы во всех трёх приложениях (в Sport — в запуске); порядок разделов настроек из `shared/apps.json`; верх настроек (гость и «Войти», имя, «Настроить профиль / цели») и низ («Выйти», одна строка синхронизации, «Открыть последнюю версию»); в Meal осталась только выгрузка дневника. |

## Sport — папка `sport-45/`

1. Собрать: `node sport-45/sport/scripts/build.mjs`. Одна команда: склеивает исходники и пишет страницу сразу в папку выпуска.
2. Проверить: `npm --prefix sport-45/sport run check`. Это около тридцати файлов проверок одной командой; ни один не лежит без запуска. Раскладку записей Sport на документы общего модуля и места в списках смотрит `check-sport-docs.mjs`.

Проверки читают собранную страницу из папки выпуска. Последняя из них сверяет, что `sport-45/index.html` и страницы упражнений — это ровно то, что сборка даёт из исходников сейчас: если исходники меняли, сначала сборка. Адреса Day и Meal в страницу не вшиты, поэтому после их выпуска Sport пересобирать не нужно.

Сборка встраивает в страницу справочник упражнений из `assets/exercise-library/v1/`, список картинок занятий из `assets/sport-icons/v1/`, список картинок вариантов из `assets/exercise-media/v1/` и общие файлы из папки `shared/` этого выпуска. Промежуточных копий нет. Списка файлов с контрольными суммами у Sport нет: то же хранит Git.

В браузере Sport смотрят сценарии ниже: `sport_store` (хранение и обмен), `sport_workout` (тренировка и журнал), `sport_families` (библиотека упражнений), `account_screens` (первый экран, вход, настройки).

## Сценарии в браузере — папка `scripts/browser/`

Сценарий открывает настоящие страницы Day, Meal и Sport в Chrome без окна и проходит путь человека: вход, запись еды, нажатие на счётчик, переход между приложениями. Так находится то, чего не видят проверки отдельных файлов: запаздывания, двойной счёт, лишние запросы.

Записи придуманные. Настоящий аккаунт и сервер не используются: запросы перехватываются в браузере, отвечает поддельный сервер из `common.py`.

Запуск всех: `scripts/browser/run.sh`. Запуск выбранных: `scripts/browser/run.sh имя имя`. Полный набор идёт около десяти минут. Код возврата 0 — все сценарии прошли.

Что нужно до запуска:

- Python с Playwright и Chrome.
- Собранный Sport: `node sport-45/sport/scripts/build.mjs`.
- Собранный Day одним файлом: `python3 scripts/build-day-standalone.py day-61`.
- Ветка каталогов в том же репозитории: `git fetch --depth=1 origin meal-libraries:refs/remotes/origin/meal-libraries`.

Сценарий `versions` читает адреса из `shared/apps.json`, переменные выпусков на него не действуют.

Как писать новый сценарий:

- Начало файла: `from common import *`.
- «Телефон» — `phone(browser, имя)`: своё хранилище, экран 393×852, московское время. Без входа приложение открывается как после «Познакомиться с …» (отметка гостя `GUEST`); первый экран — `phone(browser, имя, welcome=True)`. Один телефон с тремя приложениями — три страницы одного `phone`.
- Каталоги Meal без сети — `libraries(ctx)`. `state["offline"]=True` обрывает запросы, `hold={имя файла}` придерживает ответ, чтобы проверить отмену.
- Сценарии не запускать с 23:50 до 00:10 по московскому времени: часть шагов пишет «сегодня» и тренировку в 00:05, на границе суток `meal_store` и `meal_supplements` не проходят без ошибки в приложении.
- Более новую версию приложения изображает вкладка-заглушка: `stand_in_route(ctx)` и `stand_in(ctx, [приложение, документы, чтение, номера форматов])` с номером формата новее.
- Приложения записывают только после входа. Быстрый вход придуманным аккаунтом — `enter(page, 'meal' | 'day' | 'sport')`; у каждого приложения вход свой — соседнее приложение на том же телефоне входит своим `enter`. Вход как у человека — `sign_in_screen(page, почта, пароль)` на открытом экране «Войти», выход — `sign_out_settings(page)`; этим путём идут `meal_store`, `day_store`, `sport_store` и `account_screens`.
- Кольцо энергии читают `he(page, id, вид)` в Sport и Day и `er(page, вид)` в Meal. Вид — «съедено», «баланс» или «потрачено».
- Ждать только через `wait_for(page, условие, секунды)` или `page.wait_for_timeout`. Во время `time.sleep` поддельный сервер не отвечает, и страница его «не видит».
- «Вернулся в приложение» — `page.bring_to_front()` и событие `visibilitychange`.
- В конце — `sys.exit(finish(имя, out, checks))`.
- Числа в проверках — от придуманных записей самого сценария. Личные данные и настоящие аккаунты не использовать.
- Новый сценарий дописать в список внутри `run.sh` и в таблицу выше.

## Что где лежит в приложениях

Это описание одно на проект: с новой папкой выпуска оно не копируется. До 20.11.2026 оно лежало отдельным файлом в каждой папке выпуска. Что делает отдельный файл, обычно сказано в его первых строках.

Не править руками:

- Файлы в `shared/` внутри папки выпуска. Они меняются в корневой папке `shared/` и копируются командой `node scripts/sync-shared.mjs`.
- Блок `HAPPY_SHARED_STYLE` внутри `index.html` Day и Meal. Его встраивает `node scripts/sync-shared-ui.mjs`.
- `Happy-Day-61.html` — тот же Day одним файлом для скачивания. Его собирает `python3 scripts/build-day-standalone.py day-61`.
- В папке Sport — `index.html`, `exercises/`, `app-icons/` и `manifest.webmanifest`. Их пишет сборка из `sport/src/`.
