# Проверки Happy: что есть и что каждая смотрит

Это справочник. Запускать нужно только то, что относится к сделанной правке.

## Общие проверки — папка `scripts/`

Запуск: `node scripts/имя`. Папки текущих выпусков проверки берут сами из `shared/apps.json`.

| Проверка | Что смотрит |
| --- | --- |
| `check-shared.mjs` | Копии общих файлов в текущих выпусках побайтно совпадают с эталоном. Известные расхождения показывает предупреждением. |
| `check-shared-ui.mjs` | Общая форма аккаунта и порядок разделов настроек одинаковы в трёх приложениях. |
| `check-layout.mjs` | Страницы разбираются без ошибок, версия на странице совпадает с `shared/apps.json`, существующий дневник читается, старые адреса ведут на текущие выпуски. |
| `check-food-counters.mjs` | Счётчики продуктов: порции проходят между Day, Meal и Sport, слияние и отмена, копии модуля в выпусках одинаковые. |
| `check-app-links.mjs` | Свитчи связи между приложениями: включение и выключение пары в обе стороны. |
| `check-summaries.mjs` | Сводки между приложениями: тренировки Sport, еда Meal, порции со счётчиков в «съедено». |
| `check-meal-exports.mjs` | Выгрузки Meal: CSV, отчёты, PDF, названия способов приготовления. |
| `check-selfcare.cjs` | Отметки самочувствия Day: сохранение, группировка, пустые и нейтральные отметки. |
| `check-account-profile.mjs` | Вход, регистрация и имя профиля. |
| `check-gradients.mjs` | Движок градиентов для студий. |
| `check-studio-account.mjs` | Вход в студиях отдельный от входа в приложениях. |

## Sport — папка `sport-41/`

1. Собрать: `node sport-41/scripts/build-release.mjs`.
2. Проверить: `npm --prefix sport-41/sport run check`. Это около пятидесяти проверок одной командой.

Сборка может изменить `sport-41/index.html`. Если выпуск не планировался, вернуть файл: `git checkout -- sport-41/index.html`.

Отдельно, в браузере: `node sport-41/scripts/check-settings-layout.mjs` (экран настроек) и `node sport-41/scripts/check-families.mjs <адрес>` (семейства упражнений).

## Сценарии в браузере — папка `scripts/browser/`

Сценарий открывает настоящие страницы Day, Meal и Sport в Chrome без окна и проходит путь человека: вход, запись еды, нажатие на счётчик, переход между приложениями. Так находится то, чего не видят проверки отдельных файлов: запаздывания, двойной счёт, лишние запросы.

Записи придуманные. Настоящий аккаунт и сервер не используются: запросы перехватываются в браузере, отвечает поддельный сервер из `common.py`.

Запуск всех: `scripts/browser/run.sh`. Запуск выбранных: `scripts/browser/run.sh имя имя`. Полный набор идёт около десяти минут. Код возврата 0 — все сценарии прошли.

Что нужно до запуска:

- Python с Playwright и Chrome.
- Собранный Sport: `node sport-41/scripts/build-release.mjs`.
- Ветка каталогов в том же репозитории: `git fetch --depth=1 origin meal-libraries:refs/remotes/origin/meal-libraries`.

| Сценарий | Что смотрит |
| --- | --- |
| `versions` | Версии на страницах. |
| `counters_guest` | Счётчики в «съедено» на одном телефоне без аккаунта. |
| `counters_cloud` | То же на двух устройствах под одним аккаунтом. |
| `summaries_one_phone` | Сводки между приложениями на одном телефоне. |
| `summaries_cloud` | Сводки на трёх устройствах. |
| `day_sections` | Разделы Day и время отметок. |
| `meal_times` | Время продукта и приёма в Meal. |
| `meal_shop` | «Сборники» и настройки каталогов. |
| `meal_offline` | Каталоги без интернета. |
| `meal_supplements` | БАДы на двух устройствах и в Day. |
| `meal_supplement_counters` | Счётчик добавки в Meal, Day и Sport; предыдущий Meal открывает тот же журнал. |
| `app_links` | Связь приложений на одном аккаунте. |
| `meal_desserts` | Каталог десертов. |
| `uzbek_names` | Названия и меры узбекской кухни. |

Настройки — переменными окружения:

| Переменная | Что задаёт | По умолчанию |
| --- | --- | --- |
| `HAPPY_MEAL`, `HAPPY_DAY`, `HAPPY_SPORT` | Какой выпуск открывать. | `meal-31/`, `day-58/`, `sport-41/` |
| `HAPPY_LIBRARIES_REF` | Ветка или коммит каталогов Meal. | `origin/meal-libraries` |
| `HAPPY_CHROME` | Путь к Chrome. | `/usr/bin/google-chrome` |
| `HAPPY_PORT` | Порт временного сервера. | `8767` |
| `HAPPY_OUT` | Куда писать результаты: `имя.json` и `имя.log`. | `/tmp/happy-browser` |

Сценарий `versions` читает адреса из `shared/apps.json`, переменные выпусков на него не действуют.

Как писать новый сценарий:

- Начало файла: `from common import *`.
- «Телефон» — `phone(browser, имя)`: своё хранилище, экран 393×852, московское время. Один телефон с тремя приложениями — три страницы одного `phone`.
- Каталоги Meal без сети — `libraries(ctx)`. `state["offline"]=True` обрывает запросы, `hold={имя файла}` придерживает ответ, чтобы проверить отмену.
- Кольцо энергии читают `he(page, id, вид)` в Sport и Day и `er(page, вид)` в Meal. Вид — «съедено», «баланс» или «потрачено».
- Ждать только через `wait_for(page, условие, секунды)` или `page.wait_for_timeout`. Во время `time.sleep` поддельный сервер не отвечает, и страница его «не видит».
- «Вернулся в приложение» — `page.bring_to_front()` и событие `visibilitychange`.
- В конце — `sys.exit(finish(имя, out, checks))`.
- Числа в проверках — от придуманных записей самого сценария. Личные данные и настоящие аккаунты не использовать.
- Новый сценарий дописать в список внутри `run.sh` и в таблицу выше.

## Команды, которые меняют файлы

Это не проверки. После каждой смотреть, что изменилось.

| Команда | Что делает |
| --- | --- |
| `node scripts/sync-shared.mjs` | Копирует общие файлы из `shared/` в текущие выпуски. |
| `node scripts/sync-shared-ui.mjs` | Встраивает общую форму аккаунта в страницы Day и Meal. |
| `python3 scripts/build-day-standalone.py day-58` | Собирает Day одним файлом `Happy-Day-58.html`. |
| `python3 scripts/refresh-provenance.py day-58 meal-31` | Обновляет список файлов выпуска с контрольными суммами. С `--check` только сверяет. Запускать после последней правки кода и `git add -A`. Справки `.md` в список не входят: после правки справки ничего запускать не нужно. |
| `node sport-41/scripts/write-provenance.mjs`, затем `verify-release.mjs` | То же для Sport. |
| `python3 -I scripts/build-meal-lab.py meal-31 папка` | Собирает копию Meal для показа на телефоне до выпуска. |

При новом выпуске в этом файле меняются только номера папок.
