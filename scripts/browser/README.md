# Проверки Happy в браузере

Сценарии открывают настоящие страницы Day, Meal и Sport в headless Chrome и проходят путь человека: вход, запись еды, нажатие на счётчик, переход между приложениями. Они ловят то, чего не видят проверки отдельных файлов: запаздывания, двойной счёт, лишние запросы. 11.11.2026 так нашлись две ошибки, которых не было видно в коде: кольцо Day не обновлялось на открытом экране, а Sport спрашивал облако о съеденном только через минуту после открытия.

Все записи придуманные. Настоящий сервер не используется: запросы к нему перехватываются в браузере, отвечает поддельный сервер из `common.py` (вход с придуманным аккаунтом, таблица `app_sync` в памяти).

## Запуск

```
scripts/browser/run.sh                     # все сценарии, около 6 минут
scripts/browser/run.sh versions            # один или несколько по имени
```

Нужны Python с Playwright (`pip install playwright`) и Chrome (`HAPPY_CHROME`, по умолчанию `/usr/bin/google-chrome`). `run.sh` сам поднимает временный локальный сервер, который отдаёт репозиторий под префиксом `/happyamurio/`, как GitHub Pages (порт — `HAPPY_PORT`, по умолчанию 8767). Результаты и снимки — в `HAPPY_OUT` (по умолчанию `/tmp/happy-browser`): `<сценарий>.json` и `<сценарий>.log`. Код возврата 0 — все сценарии прошли.

Перед запуском собрать Sport: `node sport-NN/scripts/build-release.mjs`.

## Сценарии

| Файл | Что проверяет | Время |
| --- | --- | --- |
| `versions.py` | Страницы Day, Meal, Sport и самостоятельный файл Day показывают версии из `shared/apps.json`; ошибок на страницах нет (9 проверок) | 0,5 мин |
| `counters_guest.py` | Один телефон без аккаунта: Meal создаёт общий счётчик и закрыт → нажатия в Sport и Day сразу в «съедено» → Meal открыт, число не удвоилось → «−» в Sport и в самом Meal → еда из Meal плюс новая порция; гость к серверу не обращается (26 проверок) | 1 мин |
| `counters_cloud.py` | Два устройства под одним аккаунтом: Sport на первом, Meal и Day на втором; нажатия Sport видны в Day на другом устройстве при закрытом Meal; сводку Meal в облаке никто не трогает; после открытия Meal числа не удваиваются (19 проверок) | 1,5 мин |
| `summaries_one_phone.py` | Один телефон, три приложения под одним аккаунтом: сводка тренировок записана в облако один раз, приложения не переписывают её друг у друга и не качают заново (8 проверок) | 1,5 мин |
| `summaries_cloud.py` | Три устройства: Sport записывает журнал и сводку тренировок; Meal и Day на другом устройстве видят время тренировки и «съедено»; виды кольца по умолчанию; гость ничего не спрашивает у облака (20 проверок) | 2 мин |

## Как писать новый сценарий

- Начало файла: `from common import *`. «Телефон» — `phone(browser, имя)`: отдельное хранилище, экран 393×852, московское время. Один телефон с тремя приложениями — три страницы одного `phone`.
- Кольцо энергии читают `he(page, id, вид)` (Sport — `happy-energy`, Day — `careEnergy`) и `er(page, вид)` (Meal); вид — «съедено», «баланс», «потрачено».
- Ждать только через `wait_for(page, условие, секунды)` или `page.wait_for_timeout`: во время `time.sleep` Playwright не отвечает на перехваченные запросы, и страница «не видит» сервер.
- «Вернулся в приложение» — `page.bring_to_front()` и событие `visibilitychange` (см. `seen` в сценариях счётчиков).
- В конце — `sys.exit(finish(имя, out, checks))`: результат пишется в файл, прежний файл заменяется.
- Числа в проверках — от придуманных записей самого сценария; личные данные и настоящие аккаунты не использовать.
