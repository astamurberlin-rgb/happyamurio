# Тестовая сборка входа Happy

В сборке лежат текущие веб-версии Day, Sport и Meal. Для настоящего входа нужен отдельный тестовый проект Supabase. По умолчанию адрес входа использует зарезервированный домен `.invalid`.

## Ручная проверка на компьютере

Распакуйте архив в новую папку. В ней выполните команду и откройте страницу [проверки входа](http://127.0.0.1:8840/).

```sh
python3 serve-account-preview.py
```

Локальный сервер показывает собственную страницу выбора вымышленного аккаунта. Для проверки введите заметку в Day под именем Аня. Откройте ссылку в приватном окне или отдельном профиле браузера и снова выберите Аню. Вы увидите ту же заметку. Выберите Бориса в третьем профиле, чтобы открыть отдельный дневник.

Для добровольного переноса в локальной копии есть старый аккаунт с почтой `old@happy.example.invalid` и паролем `Happy-demo-123`. После ввода записи откройте управление аккаунтом и включите восстановление. Привяжите тестовый Google и выберите «Старый профиль» при входе из чистого профиля браузера.

Для проверки регистрации по почте используйте `new@happy.example.invalid` и тот же тестовый пароль. В локальной копии почта этого вымышленного аккаунта считается подтверждённой сразу.

Сервер имитирует Supabase Auth, KMS и синхронизацию. Выключение сервера очищает его память. Следующий запуск откройте в новых профилях браузера, поскольку на устройстве могут сохраниться прежние тестовые записи и сессии.

## Проверка на двух телефонах

1. В SQL Editor отдельного тестового проекта сначала выполните `supabase/app_sync_test_setup.sql`, если в проекте ещё нет таблицы `app_sync`. Затем один раз выполните `supabase/account_key.sql`. В настройках Auth включите вход по почте, Google и ручную привязку способов входа.
2. Зарегистрируйте в Google OAuth веб-клиент. Укажите HTTPS origin тестового сайта и callback проекта Supabase `https://<test-ref>.supabase.co/auth/v1/callback`. Client ID и Client Secret внесите в настройки провайдера Google в Supabase.
3. В настройках Supabase Auth укажите адрес тестового сайта и разрешите URL возврата трёх приложений. Используйте пути страниц, открывающихся со стартовой страницы сборки, с учётом завершающего слеша или имени `index.html`.
4. Соберите копию с адресом тестового проекта и его публичным ключом. В распакованном архиве выполните команду ниже, подставив свои значения. Та же команда из репозитория начинается с `python3 scripts/build-account-preview.py`. Требуется Python 3.9 или новее.

```sh
python3 build-account-preview.py ../happy-test \
  --url https://test-ref.supabase.co \
  --key sb_publishable_TEST_KEY
```

5. Для тестового симметричного ключа AWS KMS назначьте серверной IAM-роли права `kms:GenerateDataKeyWithoutPlaintext` и `kms:Decrypt` только на ARN ключа. Ограничьте разрешения контекстом шифрования `kms:EncryptionContext:project=https://<test-ref>.supabase.co` и `kms:EncryptionContext:key_version=2`. В секретах Edge Functions укажите полный ARN в `HAPPY_KMS_KEY_ARN`, доверенные тестовые учётные данные AWS в `HAPPY_AWS_ACCESS_KEY_ID` и `HAPPY_AWS_SECRET_ACCESS_KEY`. Для временных учётных данных также укажите `HAPPY_AWS_SESSION_TOKEN`. В папке с каталогом `supabase` выполните команду. Функция самостоятельно проверяет пользователя и активную сессию в Supabase.

```sh
supabase functions deploy account-key --project-ref TEST_REF --no-verify-jwt
```

6. Разместите `index.html` и каталог `happyamurio` из новой папки в корне отдельного тестового HTTPS-сайта. Откройте нужное приложение на Samsung, войдите через Google и создайте запись. Дождитесь окончания обмена, затем войдите в это приложение на чистом iPhone с тем же аккаунтом. Проверьте имя профиля и запись.
