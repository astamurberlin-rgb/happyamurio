# Тестовая сборка входа Happy

В сборке лежат текущие веб-версии Day, Sport и Meal. Для настоящего входа нужен отдельный тестовый проект Supabase. По умолчанию адрес входа использует зарезервированный домен `.invalid`.

## Ручная проверка на компьютере

Распакуйте архив в новую папку. В ней выполните команду и откройте страницу [проверки входа](http://127.0.0.1:8840/).

```sh
python3 serve-account-preview.py
```

Локальный сервер показывает собственную страницу выбора вымышленного аккаунта. Для проверки введите заметку в Day под именем Аня. Откройте ссылку в приватном окне или отдельном профиле браузера и снова выберите Аню. Вы увидите ту же заметку. Выберите Бориса в третьем профиле, чтобы открыть отдельный дневник.

Для добровольного переноса в локальной копии есть старый аккаунт с почтой `old@happy.example.invalid` и паролем `Happy-demo-123`. После ввода записи откройте «Настройки → Настроить профиль → Аккаунт → Привязать к Google». Для прежнего аккаунта пройдите предложенный шаг восстановления. Перед выбором Google подтвердите текущий пароль Happy. При следующем входе через Google выберите «Старый профиль» в чистом профиле браузера и проверьте прежнюю запись. Повторите вход по исходной почте и паролю.

Для проверки регистрации по почте используйте `new@happy.example.invalid` и тот же тестовый пароль. В локальной копии почта этого вымышленного аккаунта считается подтверждённой сразу.

Для проверки удаления откройте профиль Ани, скачайте дневник и нажмите «Удалить аккаунт». Отмена возвращает к профилю. После подтверждения снова выберите Аню через Google. Откроется новый пустой дневник. Записи Бориса по-прежнему доступны под его аккаунтом.

Локальный сервер имитирует вход, выдачу ключа, синхронизацию и удаление аккаунта. Выключение сервера очищает его память. Следующий запуск откройте в новых профилях браузера, поскольку на устройстве могут сохраниться прежние тестовые записи и сессии.

## Приватный стенд Meal

Для двух телефонов используйте один и тот же закрытый сайт Meal и его тестовый проект Supabase. Публичный ключ проекта можно включать в клиентскую сборку. Секреты и содержимое Vault доступны только на сервере.

### Серверная часть

1. Откройте SQL Editor тестового проекта. На пустом проекте выполните `supabase/app_sync_test_setup.sql` для создания таблицы записей и `supabase/account_key.sql` для работы аккаунтов. Если таблица `public.app_sync` и схема ключей уже установлены, переходите к следующему шагу.
2. Включите Supabase Vault в тестовом проекте. При первой установке выполните `supabase/account_key_vault.sql`. Миграция создаёт случайный главный ключ внутри Vault. Сохраните этот ключ при последующих обновлениях. У каждого профиля свой случайный ключ записей, который сервер хранит зашифрованным. Для установки или обновления серверной проверки выполните `supabase/account_key_vault_api.sql`. Настройка AWS отложена.
3. Выполните `supabase/account_delete.sql` в SQL Editor того же тестового проекта. Он устанавливает серверную операцию удаления собственного аккаунта по действующей сессии.
4. В каталоге с папкой `supabase` разверните функцию входа. Подставьте идентификатор тестового проекта. Функция проверяет токен в Supabase Auth и подтверждает владельца активной сессии перед выдачей ключа.

```sh
supabase functions deploy account-key --project-ref TEST_REF --no-verify-jwt
```

### Вход и приложение

1. Для уже настроенного Google сохраните текущий OAuth-клиент. При первой настройке укажите в Google HTTPS origin закрытого сайта и callback проекта `https://<test-ref>.supabase.co/auth/v1/callback`. Внесите Client ID и Client Secret в провайдер Google в Supabase Auth. Включите вход по почте, Google и ручную привязку способов входа.
2. Укажите закрытый сайт в настройках Supabase Auth и разрешите точный адрес возврата Meal. Если проверяете все три приложения, добавьте адрес возврата каждого. Учитывайте завершающий слеш или имя `index.html` в адресе страницы.
3. Для сборки статических файлов из этого архива выполните команду ниже с адресом и публичным ключом тестового проекта. В репозитории скрипт находится в `scripts/build-account-preview.py`. Требуется Python 3.9 или новее.

```sh
python3 build-account-preview.py ../happy-test \
  --url https://test-ref.supabase.co \
  --key sb_publishable_TEST_KEY
```

4. Статические файлы для просмотра находятся в `index.html` и папке `happyamurio` внутри `../happy-test`. На действующем приватном стенде Meal сохраните тот же адрес приложения и ограничения доступа. Папка `supabase` служит для настройки сервера.

### Проверка записи

На Samsung откройте приватный Meal, войдите через Google и добавьте запись с узнаваемым названием. Дождитесь окончания синхронизации. Откройте тот же адрес на чистом iPhone, выберите тот же Google-аккаунт и найдите эту запись в дневнике. Прежний профиль и запись должны открыться сразу.
