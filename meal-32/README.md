# Happy Meal · Update 32

Адрес: https://astamurberlin-rgb.github.io/happyamurio/meal-32/

Страница — `index.html`.

Meal 32 записывает только после входа в аккаунт Happy. Вход общий с Day и Sport. Записи хранит и обменивает общий модуль `shared/happy-store.js`; своего хранилища, своих запросов к серверу и гостя у Meal нет.

## Документы Meal в общем модуле

| Документ | Что в нём |
| --- | --- |
| `setup` | Разделы, счётчики, цели на день, избранное и остальные настройки дневника. |
| `products` | Свои продукты и рецепты, свои меры, выбранные продукты каталогов. |
| `snaps` | Снимки состава своих продуктов на момент записи и добавок счётчиков на момент нажатия. |
| `diary_ГГГГ`, `diary_old` | Записи еды по годам. Каждая запись еды — отдельная запись документа. |
| `supps` | Свои добавки и их приёмы. |
| `summary`, `foods` | Витрина для Day и Sport: съедено по дням и счётчики еды. Формат — `shared/happy-food.js`. |
| `foodtaps` | Нажатия на счётчики еды, сделанные в Meal. Общий документ: читают и снимают нажатия все три приложения. |

- Начальные разделы, счётчики и цели, пока человек их не менял, в хранилище не кладутся. Так новое устройство не затирает ими настроенное на другом.
- Счётчик еды принадлежит Meal. Каждое нажатие — отдельная запись у приложения, где нажали (`meal/foodtaps`, `day/foodtaps`, `sport/foodtaps`). Число на счётчике — сколько записей нажатий за день в трёх документах; оно одно во всех трёх приложениях. Meal показывает нажатия порциями в дне; в записи дней они не кладутся. Поправили или убрали порцию — меняется или убирается запись нажатия.
- У порции со счётчика добавки состав — на момент нажатия: снимок на версию состава лежит в `snaps` (`counterSnaps`), в нажатии только номер версии.
- Счётчик, убранный со страницы Day, в Meal остаётся: у него выключается показ в Day.
- Каталог добавок и их состав остаются в Meal. В витрину уходят только название счётчика, порция и числа порции.

## Каталоги продуктов

Каталогов в этой папке нет. Они лежат в ветке `meal-libraries` и обновляются отдельно от приложения. Meal читает их список при запуске и проверяет размер и контрольную сумму каждого файла. Обновление каталога не пересчитывает уже записанную еду.

## Что не править руками

- Общий стиль настроек внутри `index.html`, блок `HAPPY_SHARED_STYLE`. Его встраивает команда `node scripts/sync-shared-ui.mjs`.
- Файлы в `shared/`. Они меняются в корневой папке `shared/` и копируются командой `node scripts/sync-shared.mjs`.

## Осторожно

- `meal-docs.js`, `meal-data.js` и функцию `save()` менять только вместе с проверкой `node meal-32/checks/check-meal-docs.mjs`: она смотрит и сведение правок с двух устройств, и скорость на годе записей.
- Новый вид записи или новое поле у записи-обёртки — это другой формат: растёт номер `FORMAT` в `meal-docs.js`.
- `sw.js` обслуживает только эту папку. Картинки выпуска он отдаёт из копии на устройстве. Поэтому при выпуске в нём меняется номер версии: по нему копия собирается заново.

## После правки

Команды запускаются из корня репозитория.

1. Проверки по одной: `node meal-32/checks/имя`. Проверке «Сборников» нужен коммит каталогов, на котором собран выпуск: `HAPPY_LIBRARIES_REF=4261588 node meal-32/checks/check-shop.mjs`.
2. Хранение, вход и обмен — ещё сценарии в браузере: `scripts/browser/run.sh meal_store food_exchange`.
3. `git add -A`, затем `python3 scripts/refresh-provenance.py meal-32` — обновить контрольные суммы.
