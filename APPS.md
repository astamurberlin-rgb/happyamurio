## Параллельная работа и публикация

Перед изменением получить свежий `main`, прочитать эту карту и `DATA-STORAGE.md`.
Использовать отдельные ветки задач, не перезаписывать чужие файлы и не делать force push.
Перед слиянием проверить изменения коллег. Версии хранить в Git, при выпуске ставить теги вида `meal-v23`.
GitHub Pages публикует корень `main`; новые папки работают под префиксом `/happyamurio/`.
Перед сборкой выполнить `node scripts/sync-shared-ui.mjs`. Затем для Sport выполнить
`npm --prefix sport run build` и `npm --prefix sport run check`.
Общие элементы проверить командой `node scripts/check-shared-ui.mjs`.
Для всех приложений выполнить `node scripts/check-layout.mjs`.
Для времени питания и связки с журналом Day выполнить `node scripts/check-meal-times.mjs`.
Для CSV, отчётов и названий способов приготовления выполнить `node scripts/check-meal-exports.mjs`.
Коммитить исходники Sport вместе с результатом сборки; его `index.html` вручную не править.

Sites — отдельная рабочая копия и отдельный домен, автоматического обмена с GitHub нет.
Перед работой через Sites брать свежий код из этого репозитория; переносить обратно только изменения задачи.
Не заменять Day и Meal устаревшими копиями из проекта Sites.
Адрес Sites не превращается в GitHub Pages при этом переносе, и его данные браузера не переносятся автоматически.

## Границы проверки связки

Проверены локальные пути, ресурсы, сборка Sport и существующие автоматические проверки.
Day и Meal перенесены из main с исправлением путей, стартовых адресов и меткой версии.
При переносе логика дневников и обмена не менялась; старые копии из Sites не использовались.

Meal v22.3 позволяет менять время одного продукта или всех продуктов раздела.
Время раздела — последнее время продукта; сводка сохраняет его в `sec[k].t`,
прежние `t0` и `t1` остаются для совместимости. Day v50.4 использует это время
в ленте и CSV, включая перекусы и свои разделы. Старые сводки читаются с откатом
на `t1`, затем `t0`. Проверка использует искусственные данные без входа в аккаунт.
Meal v22.5 ограничивает время прямо при вводе и вставляет двоеточие после часов.
Часы отдельного продукта позволяют также перенести его в другой приём пищи.
Счётчики сохраняют каждое нажатие отдельной записью; их исходный раздел выбирается
по текущему времени, а перенос одной порции не изменяет остальные.

У Meal v22 и Sport v35 пока различается локальный формат обмена виджета:
Meal публикует `hd_link_meal_v1`, Sport ожидает дополненную сводку
`happy-energy-meal-v1:<owner>` либо читает `meal/link` из облака.
Meal принимает дневные агрегаты `hd_link_sport_v1.days`, Sport публикует
записи `hd_link_sport_v1.records`. Day v50.1 не содержит приёмник записей Sport.
Сам перенос в общий репозиторий не устраняет эти различия; сквозная
синхронизация с реальным аккаунтом не проверена. Не считать тесты старого
адаптера подтверждением совместимости с неизменёнными Meal v22 / Day v50.1.

Meal v22.7 убирает имитацию голосового ввода с готовыми фразами. Микрофон
открывает приветствие и поле для собственного текста. Для диктовки используется
микрофон клавиатуры; разбор запускается после отправки текста пользователем.

Meal v22.8: `meal/report.js` и `meal/report.css` отвечают за полный CSV и отчёты.
Входы — вверху «Журнала» и в Настройках, после блока связанных приложений.
CSV содержит записи выбранного периода (можно выбрать весь дневник), по одной
строке на продукт, с массой, временем, калориями, БЖУ и всеми 76 показателями
локальной базы. Пустые значения не превращаются в нули. Единицы соответствуют
`meal-data/bls40.json`: в этой локальной таблице ЭПК/ДГК, фтор и каротиноиды
уже переведены в мг; аминокислоты и прочие жирные кислоты — в г.
PDF/PNG/печать формируются на устройстве из отмеченных данных, без демо-чисел.
PDF включает все страницы A4; PNG сохраняется для выбранной страницы.
Отправка PDF использует системное меню устройства, без собственного сервера отчётов.
PDF содержит растровые страницы; CSV остаётся форматом для анализа и точных значений.
Источник состава — Max Rubner-Institut (2025), BLS 4.0; перевод названий Happy Meal.
«Без масла» относится к приготовлению; удалённый жир/шкура в описаниях мяса не переименовываются.
Обычный жареный картофель без лука — существующая запись BLS `X651013`,
получившая понятное название и приоритет для общего запроса о жареном картофеле.

В выпуске 22.8 общий журнал замеров и юридические согласия были отложены. Эта версия не меняет
синхронизацию, аккаунты, серверные схемы или подключение внешнего AI-сервиса.

Meal v22.9: свой период задаётся календарём с черновиком «От/До» и применением.
Отчёт, печать и CSV используют только период журнала; кнопки внизу, share рядом с периодом.
Первой галочкой отчёта выбирается изображение текущего виджета. Кнопка информации
продукта открывает все 76 нутриентов с переключателем порция / 100 г.

Day v50.5 / Meal v22.9 / Sport v36.3: общие замеры открываются из журнала.
Day и Meal встраивают тот же интерфейс Sport (`?embed=measurements`), а не его копии.
`shared/measurements-model.js` — слияние дат и маркеров удаления,
`sport/src/measurements-shared.js` — профиль, миграция и автоматическая зашифрованная
синхронизация через существующую строку `app_sync` sport/measurements. Серверная схема
не менялась. Даты со старых устройств объединяются, изменение одной даты выбирается
по ревизии; при одновременной правке одной даты остаётся более поздняя правка.
Проверки: `node scripts/check-measurements-shared.mjs` плюс прежний набор.
Сквозная работа с реальным аккаунтом и отдельными iOS-иконками требует проверки
на устройстве пользователя; проверены локальные приложения и моделируемый сервер.

Meal 22.14 / Day 50.11: общие продуктовые счётчики, поиск продукта и собственные порции. Проверка: `node scripts/check-food-counters.mjs`. «Добавить в Happy Day» связывает счётчик; новые нажатия и отмена передаются в обе стороны. Несвязанные счётчики Day остаются самостоятельными.
