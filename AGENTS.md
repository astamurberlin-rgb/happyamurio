# Работа с Happy

- Главные инструкции: `APPS.md` и `DATA-STORAGE.md`. Прочитать до изменения приложений.
- Актуальные входы: `day/index.html`, `meal/index.html`, `sport/index.html`.
- Day/Meal редактируются в своих папках. Sport редактируется в `sport/src/`, затем собирается.
- Старые HTML в корне — исторические файлы или переходы; не развивать их как текущие версии.
- Сохранять постоянные URL, ключи хранилища и пользовательские записи. Изменения схемы требуют миграции.
- Личные выгрузки и журналы, токены и ключи нельзя коммитить. Публичные справочники не являются дневниками.
- Перед работой обновить main, использовать ветку задачи, не затирать параллельные изменения.
- Sites не синхронизируется автоматически: сверять с main до и после работы.
- Проверки: `npm --prefix sport run build`, `npm --prefix sport run check`, `node scripts/check-layout.mjs`.
- При выпуске обновить видимую версию и `shared/apps.json`. История версий — Git.
