# Где хранятся данные Happy

Состояние на 29 октября 2026 года. Полная автоматическая синхронизация всех
дневников ещё не реализована. Этот перенос папок не меняет хранение записей.

## Репозиторий: код и общедоступные материалы

| Папка | Содержимое |
| --- | --- |
| `day/` | Happy Day |
| `meal/` | Happy Meal |
| `sport/` | Happy Sport, исходники и сборка |
| `shared/` | Карта приложений и место для будущих общих компонентов |
| `meal-data/` | Публичные справочники состава продуктов |
| `meal-img/` | Иллюстрации еды |
| `sport/data/` | Публичные справочники и шаблоны тренировок |

Личные дневники и выгрузки Apple Health, Strong и Cronometer сюда не добавлять.
Папки со справочниками не предназначены для личных данных.
История Git сохраняет версии программы, но не резервные копии дневников.

## Личные данные

| Данные | Текущее место хранения |
| --- | --- |
| Дневник и настройки Day | На устройстве в хранилище приложения |
| Записи Meal, свои продукты и рецепты | На устройстве в хранилище приложения |
| Тренировки, подходы Sport | На устройстве в хранилище приложения |
| Общие замеры тела | На устройстве по профилю; при входе — автоматически в зашифрованном виде в Supabase |
| Сводки для обмена приложений | На устройстве и через существующее облачное подключение |
| Полный резерв Sport | Файл JSON или вручную сохранённая облачная копия из настроек |
| Полный автоматический резерв Day и Meal | Пока не реализован |

Вход в общий аккаунт сам по себе не означает, что весь дневник уже сохранён
в облаке. Совместимость обмена всех трёх приложений требует отдельной проверки.
Смена аккаунта в Day 50.7 / Meal 22.11 / Sport 36.5 переключает отдельный локальный дневник с перезагрузкой страницы. Это не перенос записей и не загрузка полного дневника из облака.

## После обновления

Перенос сохраняет существующий формат и адреса хранения записей.
В том же браузерном хранилище новые страницы должны читать прежние записи.
Другой домен, браузер, устройство или установленная иконка могут использовать
другое хранилище. До удаления старой иконки проверить дневник на новом адресе.
Локальная резервная копия может исчезнуть вместе с очисткой данных браузера.

JSON нужен для резервирования и переноса, а не для каждого обновления интерфейса.
Полное восстановление Sport заменяет журнал с предварительным просмотром
и возможностью отмены; это пока не объединение старых и новых записей.

## Отчёты Meal

CSV, PDF и PNG формируются локально из дневника. Они не публикуются в репозитории
и не загружаются на сервер отчётов. CSV содержит все продукты и доступный состав
за выбранный период; для PDF, PNG и печати состав выбирается галочками.
Перед отправкой можно посмотреть страницы. Системное «Отправить PDF» передаёт
файл только тому приложению/получателю, которого выберет сам пользователь.
Эти выгрузки — копии личных данных, не замена полному резерву JSON.

## Что дальше

Отдельный этап — полная автоматическая синхронизация, работа без сети,
обработка конфликтов и импорт истории без дублей и потери ручных записей.
Выгрузки Apple Health, Strong и Cronometer в этом шаге не импортировались.

## Общие замеры тела

Один интерфейс Sport встроен в журналы Day и Meal. Локальный документ:
`happy-measurements-v1:<uid>`; без входа — суффикс `local`. Старая копия дневника
Sport не удаляется. Однократная миграция относит записи к сохранённому `sportOwner`;
при отсутствии владельца они остаются локальными. Для добавления таких записей
в аккаунт есть отдельная кнопка; совпадающие даты в профиле сохраняются.

На сервер отправляется только зашифрованный документ замеров (AES-GCM, существующий
ключ Happy), app=sport, kind=measurements. Правила RLS существующей таблицы ограничивают
чтение и запись своим user_id. Сохранение локальное сразу; отправка примерно через
секунду, обновление видимого приложения каждые 15 секунд, при возврате и восстановлении
сети. Наличие связи влияет на задержку; при ошибке записи остаются на устройстве.
Даты объединяются с ревизиями и маркерами удаления, запись на сервер условная (CAS).
Это синхронизация замеров; дневники питания и тренировок полностью не синхронизируются.

## Разделение локальных профилей

`shared/profile-storage.js` связывает ключи дневника, настроек, обмена и отмены импорта с UID аккаунта. Общий ключ входа `hd_cloud_v1` остаётся прежним. Анонимный журнал сохраняет прежние ключи; новый аккаунт начинает с отдельного журнала. При первом запуске новой версии прежний журнал с сохранённым входом копируется в область этого владельца, исходные записи не удаляются. У Sport учитывается старый `sportOwner`.

Переход между аккаунтами не переносит записи. Для переноса нужно войти в целевой профиль и загрузить его JSON. Полное восстановление заменяет только журнал этого профиля с копией для отмены. Исходная история импорта хранится в `importedHistory` и включается в последующие JSON-резервы; дневные сводки Cronometer показаны отдельно, без повторного прибавления к продуктам Meal.
