Что нового в 56 — журнал Day живёт в IndexedDB, как у Meal (с 23) и Sport (с 39). localStorage на origin один на три приложения (~5 МБ), и дневник Day был его главным жильцом — отсюда у Sport появлялось «Локальный резерв синхронизации достиг лимита».

- `day-local-store.js` — `DayLocalStore` / `dayStorage`: синхронный фасад над IndexedDB (`happy-day-private-v1` / `values`), тот же приём, что `sport-39/sport/src/local-store.js`. Кэш загружается до первого чтения журнала (`rawBaseGet` ждёт `DayLocalStore.open()`), записи уходят в IndexedDB по очереди, `flush()` ждёт их фиксации. Переезжают ключи `hd_db_v1`, `hd_db_prev_v1`, `hd_db_prev_at_v1`, `hd_backup_v1`, `hd_backup_at_v1`, `hd_bk_nag_v1`, `hd_journal_safety_v1`, `hd_test_journal_create_v1`, `hd_journal_auto_v1` — в каждой области аккаунта (`happy-user:<uid>:…`) и без префикса. В localStorage остаются `happy-auth:day`, `hd_cfg_v1`, `hd_fmt_v1`, `hd_cloud_v1`, `hd_link_*`, `hd_profile_source_v1`, стиль дуг, замеры и общие счётчики — их читают Meal и Sport или они малы.
- Перенос при первом открытии: ключи копируются в IndexedDB, перечитываются и сравниваются, только потом удаляются из localStorage; маркер `happy-day-store:indexeddb-v1`. Копия, которая уже есть в IndexedDB, главнее; отличающаяся копия из localStorage архивируется под `<ключ>:localstorage-copy:<время>` и не теряется. Любая ошибка оставляет localStorage рабочим хранилищем — ничего не пропадает.
- Прежние выпуски на этом же origin (`day-55/`, `day-54/`, …, `day/`) читают дневник из localStorage. Чтобы они не открывали пустой дневник и не восстанавливали его из облака в localStorage, при переносе для каждой области с журналом в localStorage остаётся номер формата `hd_fmt_v1` = 56 (`FMT` Day 56): старые версии открываются «старше записей» — ничего не сохраняют и не синхронизируют, показывают «Открой последнюю версию HappyDay». Это их штатная защита с v48, не новый механизм.
- Если дневник уже переехал, а IndexedDB в этом окне не открывается (другой режим браузера, ошибка хранилища) — `DayLocalStore.blocked`: приложение не загружает пустой дневник, ничего не сохраняет и не отправляет, в настройках и тосте написано, что делать.
- `day-journal-sync.js`: журнал, страховочные копии, квитанция и запись автосинхронизации читаются через `dayStorage`; каждый Web Lock после захвата перечитывает эти ключи из IndexedDB (`DayLocalStore.refresh`) и перед освобождением ждёт `flush()` — «Дневник изменился в другой вкладке» означает то же, что раньше; «страховочная копия сохранена» говорится только после фиксации в IndexedDB. Проба места в localStorage (`:space-probe-v2`) в IndexedDB не нужна — проверяется оценка браузера (`navigator.storage.estimate`), а настоящий ответ даёт сама запись. Другие вкладки слышны через `BroadcastChannel` `happy-day-store-v1` вместо события `storage`.
- В разделе «Для разработчика» → «Синхронизация и восстановление» — строка «Хранилище дневника: IndexedDB · ключей N · размер · перенесено из localStorage: N · свободно по оценке браузера …».
