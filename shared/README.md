# Общий интерфейс Happy

Образец общих элементов — Happy Meal. `happy-ui.css` задаёт поля, карточки, кнопки,
отступы и нижнюю строку версии; `happy-ui.js` рисует одну форму аккаунта и управляет
показом пароля, вводом с клавиатуры, состояниями ожидания и ошибок.

Серверные вызовы и хранение дневников остаются в приложениях и подключаются через адаптер.
Здесь не хранить личные записи, токены и ключи.

## Правила

- Порядок разделов настроек и единые названия кнопок заданы в `AGENTS.md` (раздел «Общий интерфейс и настройки»); здесь — только геометрия и общие элементы. <small>— Claude · 09.11.2026 11:55</small>
- Поля почты и пароля занимают ширину карточки. Показ пароля — внутри поля.
- «Войти» слева, «Создать аккаунт» справа в одной группе; перенос на новую строку допускается на узком экране.
- Кнопки высотой от 44 px, радиус 14 px, отступ между ними 8 px. Основная кнопка светлая, вторичная прозрачная.
- Одинаковые действия называются одинаково: «Выгрузить дневник», «Загрузить дневник» (прежде «Загрузить из файла»), «Вернуть дневник до загрузки», «Обновить связь», «Выйти».
- Дополнительные возможности приложения размещаются после общих; облачный резерв показывается только там, где он реализован.
- Настройки всегда последняя вкладка с шестерёнкой. Название, версия и дата — последний элемент настроек.
- Палитры приложений сохраняются; общие элементы используют одинаковую геометрию и типографику.

## Сборка

Общие операции нужны при изменении соответствующих общих файлов; это не проверка, которую запускают для каждой правки документа. `sync-shared-ui.mjs` меняет встроенные блоки страниц, выбранных в `shared/apps.json`; `sync-shared.mjs` копирует эталоны по `shared-files.json`. Перед запуском проверить цели, после — diff. Превью не становятся основными ради сборки.

Для целевого Sport использовать его каталог выпуска: `node sport-NN/scripts/build-release.mjs`, затем `npm --prefix sport-NN/sport run check` (NN заменить согласованным выпуском). Старые `npm --prefix sport run build/check` относятся к прежнему корневому прототипу и не являются командами текущего выпуска. Общие проверки: `node scripts/check-shared-ui.mjs`, `node scripts/check-layout.mjs`, `node scripts/check-shared.mjs` — по затронутому объёму, см. AGENTS.

Day и Meal получают общий код внутрь HTML при синхронизации, Sport — при сборке. Не править встроенные блоки `HAPPY_SHARED_STYLE` и `happy-shared-ui` вручную. Для отдельной сборки Sport через Sites копировать общий код в его `shared/` и сохранять те же исходники UI. Основные версии и адреса — `shared/apps.json`, путь к коду — APPS.

## Общий профиль · 30.10.2026

Вход содержит почту и пароль. «Создать аккаунт» открывает отдельную форму с необязательным именем. После входа «Изменить имя» сохраняет только Auth user_metadata.display_name через авторизованный PUT /auth/v1/user. GET того же пользователя обновляет имя при открытии/возврате и обновлении связи. Имя — отображение, никогда не идентификатор владельца или право доступа. Пароли и шифрование не меняются.

## Редактор градиентов · Color Studio 12.1 / Icon Studio 2.9

`happy-gradients.js` хранит общий формат независимой заливки и тему «Синий час».
Каждая точка имеет HEX, положение, яркость, насыщенность и сдвиг оттенка; у слоя
есть отдельные общие настройки. Поддерживаются сплошная, линейная, изогнутая,
радиальная и коническая заливки, два независимых источника свечения.
`happy-gradient-editor.js/css` предоставляет широкие ползунки, точный ввод и шаг ±1.
Icon Studio использует копии этих трёх модулей в отдельном Sites-репозитории.

Color Studio сохраняет прежние ключи для обоих входов: `studio.html` и
`happy-family-color-studio-v12.html`. Старые настройки импортируются в новый формат;
сам выбор темы меняет предпросмотры, не дневники приложений. Базовая тема добавляется
в общую галерею без замены выбранного пользователем оформления.
Проверка движка: `node scripts/check-gradients.mjs`.

## Фундамент общих модулей · 09.11.2026

Эталоны и копии в выпусках описаны в `shared-files.json`; `node scripts/sync-shared.mjs` копирует эталоны в `shared/` текущих выпусков (из `apps.json`), `node scripts/check-shared.mjs` проверяет побайтное совпадение (записи `divergent` — известный долг, предупреждение). Корневые `food-counters.*` и `measurements-host.js` загружают опубликованные `day/` и `meal/` — их не менять; эталон таких файлов лежит в каталоге выпуска.

- `release-notes.js` — одна история обновлений для трёх приложений: формат записи `{version, label, date, time, author, changes}`, рендер `HappyReleaseNotes.render(list)` и строка версии `HappyReleaseNotes.footer(list, label)` с датой, временем и автором. Подключён в Sport 38.3, Day 53, Meal 24.
- `happy-status.js` — словарь статусов: `HappyStatus.text('offline')`, `HappyStatus.apply(el,'cloud')`. Одни слова на одно состояние во всех приложениях, без «JSON» в пользовательских текстах. Подключается вместе с общей оболочкой.
- `happy-summaries.js` — сводки, которыми обмениваются приложения (11.11.2026): проверка сводки тренировок Sport и сводки питания Meal, показ за день (`sport.day`, `sport.workouts`, `sport.byDay`, `meal.day`), сравнение по сути (`sport.same`), короткая копия сводки Meal (`meal.compact`) и ключ в области аккаунта (`key`). Только чистые функции; подключается в Day и Meal тегом `<script>`, в Sport встраивается при сборке. Проверка — `node scripts/check-summaries.mjs`. С Sport 40.4 / Meal 27.3 / Day 57.5 `meal.day(сводка, дата, документ счётчиков)` прибавляет к «съедено» порции со счётчиков, которые Meal ещё не посчитал (сводка называет посчитанные в `days[дата].cs` и решённые самим Meal в `skipped`); правило описано в начале файла и в `DATA-STORAGE.md`.
- `happy-links.js` — кнопки соседних приложений: якорь `<a data-happy-app="day|meal|sport" href="../day-54/">` получает адрес текущего выпуска из `/happyamurio/shared/apps.json` при открытии страницы (`HappyLinks.load()`, авто на `DOMContentLoaded`); статический href — запасной. Выпуск соседа больше не требует точечного выпуска у остальных. Подключён в Day 54, Meal 26, Sport 38.5.
- `happy-settings-developer.js` — скрытый раздел `<section data-happy-section="developer" hidden>`: долгое нажатие 1,2 с на `[data-settings-developer="toggle"]` (строка версии) открывает, кнопка `[data-settings-developer="hide"]` закрывает; состояние на сеанс (`sessionStorage`, ключ по `data-happy-appearance-app`). Подключён в Day 54, Meal 26; у Sport то же поведение в своём `settings-layout.js`.

## Общие библиотеки (из прежнего AGENTS.md, 13.11.2026)

- Картинки занятий Sport лежат один раз в неизменяемой библиотеке `assets/sport-icons/v1/` (постоянный адрес, подключается в `sport/scripts/build.mjs` через `SPORT_ICON_LIBRARY`); файлы внутри `v1/` не менять — изменённый набор идёт в новую папку `v2/`, на которую переключается следующий выпуск. Мастера полного размера — в `icon-studio/sport-icons/`.
- Справочник упражнений, оборудования и групп мышц Sport — `assets/exercise-library/v1/` (`exercises.json`, `equipment.json`, `exercise-muscles.json`, `manifest.json` с хешами). Выпуск встраивает её при сборке через `sport/scripts/seed.mjs`; в `sport/data/seed.json` упражнений больше нет. `id` устойчивы и не удаляются; папка только растёт с обновлением манифеста, несовместимая схема — новая папка `v2/`. Проверки читают справочник только через `seed.mjs`.
- `food-counters.js`: эталон — копия текущего выпуска Day (`{day}/shared/food-counters.js` в `shared/shared-files.json`); копии выпусков должны совпадать с ним побайтно (`node scripts/check-food-counters.mjs`). Корневой `shared/food-counters.js` — прежняя версия, выпуски её не используют.
