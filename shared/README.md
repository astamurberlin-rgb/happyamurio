# Папка shared: общие части трёх приложений

Здесь лежат исходники того, что одинаково в Day, Meal и Sport. В выпуски они попадают копиями. Личные записи, пароли и ключи здесь не хранить.

## Как общие файлы попадают в приложения

- `node scripts/sync-shared.mjs` копирует файлы из этой папки в папку `shared/` текущих выпусков. Список файлов — `shared-files.json`.
- `node scripts/sync-shared-ui.mjs` встраивает общую форму аккаунта внутрь страниц Day и Meal.
- В Sport общий код попадает при сборке: `node sport-41/scripts/build-release.mjs`.
- Обе команды `sync` меняют файлы. После них смотреть, что изменилось.
- Встроенные в страницу блоки `HAPPY_SHARED_STYLE` и `happy-shared-ui` руками не править: следующая сборка их перезапишет.

`node scripts/check-shared.mjs` проверяет, что копии в выпусках совпадают с эталоном.

## Известные расхождения

Сейчас шесть копий отличаются от эталона. Проверка показывает их предупреждением, а не ошибкой:

- `happy-ui.js` в Day и в Sport;
- `happy-ui.css` в Meal;
- `food-counters.css` в Meal;
- `profile-storage.js` в Meal: у Meal своя версия с проверками входа;
- `measurements-host.js` в Day: файл в Day не подключён к странице.

У четырёх файлов эталоном служит копия в текущем выпуске Day, а не файл в этой папке: `happy-appearance.css` (здесь его нет), `happy-reference-themes.js`, `food-counters.js`, `profile-storage.js`. Файлы `food-counters.js` и `profile-storage.js` в этой папке старее, чем в выпусках.

## Что за файлы

| Файл | Для чего |
| --- | --- |
| `apps.json` | Карта приложений: папка и версия текущего выпуска, предыдущий выпуск, порядок разделов настроек. По ней кнопки соседних приложений и проверки находят текущие версии. |
| `shared-files.json` | Список общих файлов и их эталонов для `sync-shared` и `check-shared`. |
| `happy-ui.css`, `happy-ui.js` | Общий вид: поля, карточки, кнопки, форма аккаунта. Образец — Happy Meal. |
| `release-notes.js` | История обновлений внизу настроек: версия, дата, автор, что изменилось. |
| `happy-status.js` | Словарь статусов: одни слова на одно состояние во всех приложениях. |
| `happy-links.js` | Кнопки соседних приложений берут адрес текущей версии из `apps.json`. |
| `happy-app-links.js` | Свитчи связи между приложениями. |
| `happy-summaries.js` | Сводки, которыми обмениваются приложения: тренировки, еда, порции со счётчиков. |
| `happy-settings-developer.js` | Скрытый раздел «Для разработчика»: открывается долгим нажатием на строку версии. |
| `happy-appearance.js` | Выбор оформления. |
| `happy-reference-themes.js`, `happy-gradients.js`, `happy-gradient-editor.js`, `happy-gradient-editor.css` | Темы и градиенты для Color Studio и Icon Studio. |
| `happy-studio-account.js` | Вход в студиях, отдельный от входа в приложениях. |
| `food-counters.js`, `food-counters.css` | Счётчики продуктов. |
| `measurements-model.js`, `measurements-host.js` | Замеры тела: модель записей и вкладка «Замеры тела» в журнале. |
| `profile-storage.js` | Журнал принадлежит одному аккаунту; записи гостя и разных аккаунтов не смешиваются. |
| `imported-history.js` | Показ истории, перенесённой из других трекеров, только для чтения. |

Общего кода входа (`happy-auth.js`) и общей оболочки с шапкой и вкладками пока нет.

## Общий вид

- Поля почты и пароля занимают ширину карточки. Показ пароля — внутри поля.
- «Войти» слева, «Создать аккаунт» справа в одной группе. На узком экране допускается перенос.
- Кнопки высотой от 44 px, радиус 14 px, отступ между ними 8 px. Основная кнопка светлая, вторичная прозрачная.
- Одинаковые действия называются одинаково: «Выгрузить дневник», «Загрузить дневник», «Вернуть дневник до загрузки», «Обновить связь», «Выйти».
- Палитра у каждого приложения своя. Общие элементы используют одинаковую геометрию и шрифты.
- Имя в профиле — только отображение. Оно не служит идентификатором владельца и не даёт прав.

## Порядок настроек

Аккаунт → Связанные приложения → Приложение → Данные → «Для разработчика» → история обновлений и версия. В Day раздела «Данные» нет.

- В «Аккаунте» на виду только вход и одна строка состояния.
- Связанные приложения стоят стопкой сразу под аккаунтом: название открывает приложение, свитч включает и выключает связь пары в обе стороны.
- «Выбрать оформление» — первый блок раздела «Приложение».
- В «Данных» только пользовательское: отчёты Meal, счётчики записей Sport.
- Всё служебное лежит в «Для разработчика»: резервная и облачная копия, CSV, импорт из трекеров, «Обновить связь», диагностика синхронизации. Новый служебный блок сразу ставить туда.
- Настройки — последняя вкладка, иконка — шестерёнка.

## Библиотеки Sport

- Картинки занятий лежат в `assets/sport-icons/v1/`. Файлы внутри `v1/` не менять: изменённый набор кладётся в новую папку `v2/`. Исходники полного размера — `icon-studio/sport-icons/`.
- Справочник упражнений, оборудования и групп мышц лежит в `assets/exercise-library/v1/` и встраивается в Sport при сборке. `id` упражнений не меняются и не удаляются. Несовместимая схема — новая папка `v2/`.
