# Просмотр замеров Sport в Day: автономный прототип

6 ноября 2026. **Не подключён к приложениям и не опубликован.**

## Что сделано

Подготовлен небольшой модуль чтения зашифрованного Sport journal и его
неизменяемой проекции замеров. Только один GET к существующему namespace
`sport/journal` текущего владельца. Записей, импорта, объединения дат,
миграции, нового аккаунта, refresh или сохранения в Day нет. Старый
`sport/measurements` не читается и не включается как второй источник.

Sport остаётся временным единственным источником замеров. Это первый шаг к
одному профилю и общим записям, а не предложение хранить независимые версии.

## Основания в точных исходниках

- Day: `386ebc402e5fdc37310920304bf167086c30f342`.
- Sport: `b00d4474a79f43a0bd64f23b71556f6a7409fe9f`.
- SHA-256 конкретных изученных файлов и границы небольшого извлечения чистых
  validators перечислены в `provenance.json`. Полные Sites не скопированы.
- Day `dist/day/index.html:1900–1925,1954–1960` и Sport
  `sport/src/happy-auth.js:5,46–52`: алгоритм PBKDF2-SHA-256, 600000 итераций,
  соль `happyday-sync-v1:<uid>`, AES-GCM-256 совпадают. Совпадение фактического
  ключа требует того же UID и пароля. Разные origins и ключи хранения входа
  (`hd_cloud_v1`, `auth_readonly_hd_cloud_v1`) не создают общей сессии.
- Day `dist/shared/measurements-host.js:7–9` открывает отдельную ссылку Sport
  при другом origin. postMessage используется только для высоты iframe.
  Ни токены, ни ключи, ни записи туда добавлять нельзя.
- Sport `sport/src/controlled-sync-ui.js:10–12` задаёт точный owner-filter,
  namespace, метаданные строки и AAD `uid|sport|journal`.
- Sport `sport/src/data-transfer.js:3–7,20–21` определяет полный envelope и
  допускает у замеров нули, null, любые конечные числа, неизвестные поля,
  повторяющиеся и невозможные календарные даты вида YYYY-MM-DD. Чистый
  validator скопирован с нужными pure helpers без UI/хранилища/автозапуска.
  Его нормализующий результат намеренно не используется для проекции.
- `measurementTrash` входит в backup, но его внутренняя структура этим
  validator не проверяется. Прототип не нормализует и не переносит корзину.
  Day получает только факт наличия этого поля, без содержимого или ложного
  предположения о количестве записей.

## Проверенные свойства

- Фиксированный HTTPS backend и GET; без body/cookies/redirect/cache/referrer,
  без refresh, записи auth или fallback на legacy namespace.
- До и после каждого await проверяются текущий owner/profile, ссылка session,
  token/expiry, CryptoKey, поколение и свежий persisted fence. Пустой или
  истекающий вход не вызывает запрос. Это проверка согласованности доверенного
  адаптера, не самостоятельная аутентификация произвольного объекта.
- Новая проверка очищает прежнюю проекцию; поздние ответы, смена ключа/аккаунта,
  logout, отмена и dispose не возвращают старый результат в current state.
- Общий deadline 20 секунд ограничивает ожидание fetch/body/decrypt/digest,
  даже если операция игнорирует AbortSignal. Позднее завершение отсекается
  поколением запроса; старый timeout не меняет новый результат.
- Ответ читается потоково с лимитом 4,1 МБ; ciphertext ограничен исходным
  лимитом 4 млн base64-символов. Проверяются одна/ноль строк, владелец,
  namespace, версия, at, IV, AES-GCM/AAD и envelope полного Sport journal.
- Живые замеры сохраняют порядок, повторяющиеся даты, 0/null/отрицательные и
  большие конечные числа, дополнительные поля. Ничего не сливается по дате.
- Указанные опасные prototype-ключи отвергаются, а не вычищаются. Пустая
  строка облака, пустой допустимый список и ошибка расшифровки различаются.
- Корзина, тренировки, заметки, credentials и полный journal не попадают в
  возвращённую проекцию. Неизвестные значения в самих live measurement records
  сохраняются; будущий UI должен отображать их как текст, не HTML.

Тесты искусственные, с реальным WebCrypto AES, запрещёнными ambient network и
storage API и внедрённым fake transport. Проверены зависшие fetch/body и
поздние decrypt/digest, out-of-order ответы и отсутствие сохранения данных.
**65 тестов пройдено, 0 ошибок.** Результат выполнения находится в
`test-results.tap`. `npm run check` также проверяет синтаксис обоих модулей.
При invalidate/dispose состояние очищается сразу; если транспорт игнорирует
abort, прежний promise может завершиться лишь к исходному deadline, без
повторного показа данных.

## Что не решено и почему модуль не подключён

1. Для этого способа Day получает весь зашифрованный Sport journal и
   расшифровывает его в оперативной памяти, хотя наружу отдаёт только замеры.
   Это не серверный доступ только к полям замеров. Нужно выбрать и подтвердить
   такой охват доступа или отдельно проектировать безопасную проекцию.
2. Нужен доверенный Day-adapter с настоящей проверкой physical auth fence,
   профиля и поколения. Он ещё не создан и не подключён. Совпадение алгоритма
   ключа не доказывает одинаковый реальный пароль/UID, доступ или RLS.
3. Нужны UI/lifecycle hooks, которые немедленно очищают экран и сохранённые
   ссылки на результат при logout/key/storage/pagehide/navigation. Уже
   переданный объект JavaScript нельзя отозвать; одного `getState()` мало,
   если UI продолжает показывать свою старую копию. Здесь UI отсутствует.
4. Нужны отдельно разрешённый тестовый аккаунт и проверка actual CORS/RLS,
   service worker/PWA cache, login/logout/password changes, Safari и устройств.
   Личный аккаунт не использовался как тестовый стенд.
5. Это снимок последней прочитанной облачной копии, а не доказательство
   актуальности всех локальных записей Sport. `rowAt` не используется как
   revision/conflict rule. Snapshot digest/позиция не становятся record ID.
6. Нет миграции в общий профиль/records, разрешения конфликтов, команды
   редактирования или восстановления. Эти вопросы остаются в отдельном плане.

Рекомендация: сохранить этот небольшой offline пакет для обзора. Следующий
шаг после принятия границ доступа — отдельный Day-adapter и UI с очисткой при
смене контекста, затем проверка на изолированном аккаунте. Не заменять Day
старым GitHub кодом и не включать параллельно legacy measurement writer.

Исходные Day/Sport checkout и существующий Sport candidate оставлены без
изменений. Новые тесты не подтверждают production/browser acceptance.
